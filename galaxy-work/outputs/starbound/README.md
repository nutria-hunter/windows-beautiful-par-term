## 5.8 원칙을 코드로 — 해상도는 크기를 따르고, 조명은 장면 하나를 따른다

사용자 질문(“소형 개체 조악함을 구조적으로 막을 원칙이 뭐냐”)에 대한 답으로 **네 가지 원칙**을 정하고 코드에 넣었다.

**P1. 해상도는 겉보기 크기를 따로다** — `lodStep(apparentPx)`: >64px → **4px**(행성), >16px → **2px**(함선·암석), 그 외 → **1px**(먼 점). 먼 물체를 4px 블록으로 그리는 것이 “무지성 저해상도”의 정체였다. 이제 객체는 격자를 고르지 않고 함수에 묻는다.
**P2. 객체는 자기 조명을 발명하지 못한다** — `shade3(lit, base, hi, lo)`가 행성과 같은 광원에서 3톤을 돌려준다. 3톤 + 밝은 엣지는 “덩어리”가 아니라 “물件”로 읽히는 최소 조건이다.
**P3. 배치는 `placeAt` 하나** (5.7) — `check_placement.py`가 어기면 설치를 막는다.
**P4. 색은 카나가와 팔레트 안에서만** — 액센트도 팔레트의 5색(waveRed·orange·springViolet·boat yellow·crystalBlue)만 쓴다.

### 이번에 반영된 것

- `lodStep` / `shade3` 도입, **정거장 척추를 `shade3`로 이관**(원칙의 실사용 예)
- **적함 크기 복원**: 5.7에서 `depth`를 0.5로 줄이고 이탈 시 0.05배로 줄였더니 함선이 **점만 해져 “생성 안 됨”처럼 보였다** — 0.72로 올렸다. 이게 워프함선 체감 버그의 정체였을 가능성이 크다.
- **정거장을 더 멀리 + 궤도 다양화**: 반경 0.036~0.024 → **0.022~0.014**, 레인 0.12~0.88 → **0.06~0.94**

### 남은 것

- 정거장 방열핀·도킹베이 삽입(앵커가 어긋나 이번엔 미적용), `lodStep`을 각 객체의 `placeAt` 호출에 실제로 연결하는 리팩터

검증: `check_placement.py` 통과 · `shader-lint` 무이슈(14 컨트롤) · 4K 0.38ms.

아카이빙: 5.7은 `-v5.7.glsl`, 현재 5.8은 `-v5.8.glsl` 스냅샷과 동일.

## 5.7 배치 규칙의 구조적 강제 · 남은 지글거림 수정 · 함선 2px 격자

**전수 감사에서 4곳이 규칙 밖**이었다: 혜성 머리/비드 · 별동별 머리/비드 · 순찰함 · 채굴 드론 — 모두 `pixel - snapFine(...)`(블록 중심 + 미세 위치)이라 소행성과 같은 지글거림 원인이었다. 전부 **단일 배치 함수**로 통일했다.

**구조적 강제(요청)**: 이제 움직이는 모든 것 — 행성·함선·암석·혜성·게이트 — 이 `placeAt` 한 함수만 지난다. 새 기능이 규칙을 어기면 **툴체인이 막는다**: `galaxy-work/work/check_placement.py`가 원시 `pixel - ...` 오프셋을 찾으면 설치 전에 실패한다(현재 통과). 이제는 기억이 아니라 검사가 규칙을 지킨다.

**함선 2px 격자**: 행성 4px와 프래그먼트 사이인 `chunkLocal = placeAt(...,2.0)` — 고전게임 톤 유지, 이동은 부드럽게.

**함선 생성 안전화**: 적함 bbox를 60×40으로 다시 넓혀 어떤 함종도 잘리지 않게 했다(5.4의 단검 웨지가 bbox에 잘리던 문제 재발 방지).

**피격 이펙트 1/4**: 쉴드 육각 0.8→**0.30**, 교전 쉴드 0.9→**0.34**, 피격 섬광 0.5→**0.18**, 격추 폭발 1.1→**0.40**(양측), 실드파괴 섬광 1.5→**0.40** — 4K에서 1~2 물리픽셀 섬광.

검증: `check_placement.py` 통과 · 브레이스 균형 0 · `shader-lint` 무이슈(14 컨트롤) · 4K 0.38ms.

⚠ 시그니처 변경 기록: 인자를 추가할 때 **호출부와 기존 지역변수(`px`)까지** 챙기지 못해 두 번 깨진 상태로 설치됐다(둘 다 앱 폴백이 화면을 보호했고, 같은 턴에 수정·재설치). 앞으로 시그니처를 바꾸면 `check_placement.py` + 렌더 + lint 3종을 **설치 전 게이트**로 돌린다.

아카이빙: 5.5는 `-v5.5.glsl`, 현재 5.7은 `-v5.7.glsl`.

## 5.5 소행성 지글거림 — 원인 확정 및 수정

**확정한 원인**: 소행성의 모양을 **블록 중심(4px 격자)에서 평가**하는데 위치는 **1px씩 미끄러지고** 있었다. 그러면 경계 블록의 판정이 **서브픽셀마다 뒤집혀** 가장자리가 지지직거린다 — 위치 스냅(`snapFine`)도, 실루엣 단순화도, 톤다운도 이 원인은 건드리지 못했다.

**수정**: 샘플링을 **프래그먼트**에서 하고 **특징만 블록으로 양자화**한다.

```glsl
// 위치는 물리픽셀에 앵커(1px씩 이동) — 모양은 자기 4px 격자 위 — 샘플링은 프래그먼트
vec2 d=floor(fineLocal(fragCoord,rock,px));
```

이러면 암석은 **모자이크가 통째로 평행이동**한다: 블록 크기는 4px 픽셀아트 그대로이고, 격자 자체가 1px 단위로 미끄러지므로 경계가 다시 뒤집히지 않는다. (블록 중심 샘플링 = 매 서브픽셀마다 경계 블록이 통째로 뒤집힘 = 지글거림)

⚠ 정직 기록: 이번 수정은 오프스크린에서 **수치로 증명하지 못했다** — 암석 색(회색)이 성운과 겹쳐 마스크가 13,365px(실제 암석 ~1,000px)를 잡아 IoU 측정이 무의미해졌다. 수정은 구조적 근거(샘플링 지점 vs 특징 양자화 분리)로 적용했으니 **라이브 화면 판정이 필요**하다. 여전히 지글거리면 남은 선택지는 둘 중 하나다: (a) 위치를 블록 격자에 스냅해 **완전 고정 래스터**(지글거림 0, 대신 4px 스텝 이동), (b) 암석 특징을 2px로 낮춰 지글 폭 자체를 줄이기.

검증: `shader-lint` 무이슈(14 컨트롤) · 브레이스 균형 0.

아카이빙: 5.4는 `-v5.4.glsl`, 현재 5.5는 `-v5.5.glsl` 스냅샷과 동일.

## 5.4 함선 생성 버그 · 적함 5색 액센트 · 궤도 엘리베이터 디테일 · 기동 둔화

**“워프인/아웃 함선이 제대로 생성 안 되는 버그”의 원인을 찾았다**: 함체 bbox 검사를 `abs(s.x)<30` 으로 두고 있었는데, 5.3에서 넣은 **단검 웨지는 ±34까지 뻗는다** — 그래서 새 함종은 **잘려서** 그려졌다(사라지거나 반쪽만). bbox를 여유 있게 넓혔다: 적함 44/26, 아군방어함 48/26, 아군함대 58/30.

**적함 5색 액센트**: 적 편대가 핑크 한 색으로 몰려 심심했다. 이제 **함종마다 팔레트의 다른 액센트**를 쓴다 — 시드=waveRed `(195,64,67)`, 크랩=burnt orange `(186,112,72)`, 스파이어=springViolet `(149,127,166)`, **웨지=boat yellow `(176,134,72)`**, 하이브마더=crystalBlue `(126,156,216)`. 종류별 부속도 추가(웨지 격납고 베이·시드 날개 슬롯·크랩 발톱 끝) — 실루엣과 색이 함께 변한다. 엔진 불꽃도 분홍에서 주황으로.

**궤도 엘리베이터/레일 디테일**: ① 레일을 두 겹(굵은 띠 + 밝은 상단 엣지)으로 ② 케이블에 **점선 결**을 넣어 실처럼 보이게 ③ 정거장을 **허브+암+점등 포트**로 키우고 금색 창문 몇 개를 넣었다.

**기동 둔화**: 전투 함선의 **진입 램프를 2.2→5.0초**(시차 0.45→0.70), 아군 방어함 진입 1.2→4.0초로 늘렸다. 아군 함대 순찰도 수명 22/16→**90/60초**로 늘려 화면을 천천히 가로지른다.

검증: 브레이스 균형 0 · `shader-lint` 무이슈(14 컨트롤) · 4K 0.38ms.

⚠ 컴파일 기록: 액센트 색을 엔진 줄에서도 쓰려 했는데 `accent`가 `if(hull)` 블록 안에만 선언돼 미정의(2곳) → 엔진은 직접 색으로 지정했다. 범위 밖 변수 재사용을 또 한 번 확인하는 계기가 됐다.

아카이빙: 5.3은 `-v5.3.glsl`, 현재 5.4는 `-v5.4.glsl` 스냅샷과 동일.

## 5.3 스타게이트 측면화 · 소행성 톤다운 · 정거장 잉크톤 · 적함 웨지

**스타게이트를 측면으로 돌렸다**: 정면으로 쳐다보는 링은 지나가면서 어색했다. 이제 `vec2 de=vec2(d.x/0.30,d.y)`로 **세로로 긴 타원**이 되어, 화면을 스쳐 지나가는 옆모습으로 읽힌다. 입구도 같은 타원이라 얇은 슬릿처럼 보인다 — 뮤럴에서 유일하게 절대 정면으로 보이면 안 되는 형상이다.

**소행성은 칙칙하게**: ① 광맥·채굴 드론·채굴 빔을 **전부 끔**(`bool mined=false` 플래그로 코드 경로는 보존) ② 팔레트를 한 단계 어둡고 탈색된 회색으로 내림(`88,90,96`→`72,74,78` 등) ③ 실루엣을 **매끄러운 3엽 원**으로 단순화(울퉁불퉁한 로브는 경계 픽셀이 계속 뒤집혀 지직거림을 키웠다) ④ 벨트 통과 시간 30~45→**60~90초**(속도 절반 — 빠를수록 지직임이 눈에 띄었다).

**정거장 색 통일**: 태양전지 판을 파란색에서 **잉크 톤**(`32,42,61` / `45,61,78`)으로 바꿔 성운·행성과 같은 색가족으로 넣었다(따로 놀던 문제 해결).

### 남은 3건 중 진행한 것

- **적함 웨지**: 만타를 **스타디스트로이어식 단검 웨지**로 교체 — 뱃머리가 뾰족하고 꼬리로 갈수록 넓어지며, 위에 **함교 탑**, 배에 **격납고 노치**. 실루엣만으로도 위압감이 생겼다.
- **함선 팔레트**: 아군 = 쿨그레이 + 금색 창문, 적함 = waveRed/springViolet(5.0에서 완료) ✓
- **정거장 디테일**: 이번엔 색만 정리했고, 도킹베이·방열핀·반전 링 추가는 아직 남음 ✗

검증: 브레이스 균형 0 · `shader-lint` 무이슈(14 컨트롤) · 4K 0.37ms. ⚠ 게이트 옆모습은 오프스크린 렌더에서 색 마스크가 행성 표면을 잡아내 **육안 확인을 못 했다** — 코드상 타원 변형만 적용된 상태이니 라이브 화면에서 봐주셔야 한다(정직 기록).

아카이빙: 5.2는 `-v5.2.glsl`, 현재 5.3은 `-v5.3.glsl` 스냅샷과 동일.

## 5.2 장엄한 페이싱 · 순식간 이펙트 · 원거리 워프아웃 · 함선 고해상도

**이벤트 주기를 전부 늘렸다**(장엄한 스페이스 오페라 톤): 혜성 240→**420초**, 별동별 45→**85초**, 순찰 260→**420초**, 스타게이트/정거장 150→**250초**, 소행성 무리 150→**300초**, 적함 침공 200→**420초**, 아군함대 180→**340초**. 이제 이벤트는 드물고 간격이 길다.

**포격은 순식간·극소**: 비행 창을 0.42→**0.10초**(적함), 0.45→**0.12초**(아군), 대공포격 0.55→**0.16초**로 줄였다. 탄은 **길이 3.5화면px·폭 0.5px**로 짧고 얇으며, 피격 창도 0.28→**0.12초**. 섬광 크기 추가 축소: 쉴드 육각 1.2→**0.8**, 지표/선체 피격 0.7→**0.5**, 격추 폭발 1.6→**1.1** 논리px.

**원거리 워프아웃**: 이탈 시 함체를 **늘리는 대신 줄이는** 방식으로 바꿔, 멀리서 빛이 오므라들며 사라지는 “은유적 퇴각”이 된다.

**순찰 거리 랜덤화**: 이벤트마다 원거리 계수(0.26~0.56)를 시드로 뽑아, 가까이 도는 편대와 멀리 궤도에 머무는 편대가 섞이게 했다.

**함선은 4px보다 정밀하게**: 요청대로 함선 함체만 프래그먼트 단위(`fineLocal`)로 그려 장갑 디테일이 살도록 했고, **소행성은 4px 블록 픽셀아트로 유지**했다(두 규칙을 분리).

## 5.1 4px 픽셀아트 원칙 복구 · 발사/피격 정렬 · 정거장·게이트 재작업

**디자인 원칙을 다시 맞췄다**: *모양은 4px 블록 픽셀아트, 움직임만 1px 단위로 부드럽게*. 4.9에서 도입한 `fineLocal`(프래그먼트 기반 오프셋)은 소행성·채굴 드론·순찰함의 **모양까지 화면픽셀 해상도로** 만들어 버려 “고해상도”가 됐다(사용자 지적). 이제 오프셋은 다시 **블록 격자(`pixel`)** 에서 재고, **위치만** `snapFine`(1px)으로 움직인다 — 블록 느낌도 유지하고 미끄러짐도 유지.

**발사/피격 위치 정렬**: 허공 발사의 남은 원인은 **아직 도착하지 않은 함선을 표적으로 삼는 것**이었다(도착 전 함선은 그려지지 않으니 탄이 빈 곳으로 날아가고 빈 곳에 맞았다). 이제 ① 교전(듀얼)은 아군이 도착한 뒤(age>3.8)에만 ② 아군의 표적도 **도착한 적함만**(`tgtOk`/`impTgt`) ③ 충돌 섬광도 같은 조건으로 그린다.

**정거장 재작업**: 지글거림의 원인은 **각도 기반 패턴**(`mod(floor(ang*3.8),3)`)이었다 — 정거장이 이동하면 각 픽셀의 각도가 변해 창문 무늬가 같이 흔들렸다. 이제 창문을 **이산 점 12개**(각 점을 직접 좌표로 계산)로 바꿔 이동해도 패턴이 고정된다. 태양전지의 **체커 패턴도 제거**(평평한 면 + 밝은 앞전) — 디테일은 유지하면서 지글거림만 없앴다.

**스타게이트 다듬기**: 링을 두께 3.4px의 두 면(좌상단 lit)으로 키우고, 입구는 **동심 먹 밴드**(행성의 구름 띠처럼 반지름의 연속 함수)로 다시 그렸다 — 격자 패턴이 없어 표류해도 끓지 않는다.

검증: `v51-stat.png`(평평한 태양전지 + 이산 창문 점 + 항법등) · 브레이스 균형 0 · `shader-lint` 무이슈(14 컨트롤) · 4K 0.44ms.

⚠ 복구 기록: 편집 중 브레이스 불균형으로 한 번 컴파일이 깨졌다(라이브는 v5.0이라 무사 ✓). **정상 컴파일되던 v5.0 스냅샷으로 되돌린 뒤** 의도한 변경만 다시 적용했고, 적용 후 브레이스 균형과 렌더를 확인하고 설치했다. 긴 블록을 통째로 치환하는 편집은 이렇게 위험하므로, 이후에는 **한 줄 조건 추가/플레그 변수** 방식으로 구조를 바꾸지 않는 편집을 우선한다.

아카이빙: 5.0은 `-v5.0.glsl`, 현재 5.1은 `-v5.1.glsl` 스냅샷과 동일.

## 5.0 교전 속도 극감 · 이펙트 1px화 · 스타게이트 재설계(테마 일체감)

**함선 기동을 행성급으로 낮추었다**: 교전 수명을 30~40초 → **130~170초**로 늘렸다. 실측 이동 속도 **2초에 0.0205 화면폭**(0.010/s) — 행성(0.0087/s)과 거의 같은 수준이다. 격추 시각도 재배치(적함 `35+13·id`, 아군 `45+15·id`)해서 130초 교전 동안 손실이 고르게 퍼진다.

**모든 포격 이펙트를 1px·짧게**: 이제 탄은 **프래그먼트 단위**로 재서 그린다.

**스타게이트 재설계 — 머신이 아니라 벽화로**: 이전 버전은 회색 분할링·셰브론·백색 트림으로 기계처럼 보여 테마와 따로 놀았다. 지금은 **빛나는 장식을 전부 제거**하고 ① 살짝 밝은 좌상단 엣지를 가진 **먹빛 링 2겹** ② **디더 먹 소용돌이**(안쪽으로 감기는) ③ 성운의 등고선처럼 얇은 **방사 줄기** ④ **종이접기풍 파일런 3개**(투톤·무광) ⑤ 입구를 도는 **느린 점 2개**만 남겼다. 팔레트의 잉크 톤(sumiInk 계열 + ink-blue) 안에서 끝나므로 행성·성운과 한 덩어리로 읽힌다.

## 4.9 지글거림 근본 해결(모든 객체) · 벨트 이탈 · 스타게이트 재설계 · 색 일관성

**지글거림의 근본 원인**: 객체의 모양을 **논리 4px 격자**에서 평가하는데 물체는 그 사이를 미끄러지니, 패턴이 매 블록마다 **다시 끓었다**. 행성이 멀쩡한 이유는 **느리고 거대해서** 1px 재평가가 눈에 안 띄기 때문이다.

**해결: `fineLocal(fragCoord, center, px)`** — 행성의 `bodyLocal` 규칙을 **화면 해상도로** 가져왔다(원점을 물리픽셀 격자에 앵커 + **프래그먼트에서** 오프셋 계산). 적용: **소행성 무리·채굴 드론·순찰함**. 워프 함대는 이미 앵커 방식이라 안 지글거렸고(사용자 관찰과 일치), 이제 순찰도 같아졌다.

**소행성 화면 끝 “뿅”**: 벨트 끝점이 `aspect+0.18`이라 뒤따르던 암석이 화면 안에 남은 채 이벤트가 끝나 사라졌다 → `aspect+0.62`로 늘려 **벨트 전체가 화면 밖으로 빠져나가게** 했다.

**스타게이트 재설계**: 9분할 외곽 링(두 톤 교대) + **밝은 셰브론 9개** + 크리스탈블루 중간 트랙 + 내부 트랙 + **디더 아이리스(5단·4단, 느리게 호흡)** + **보라 베인 6개 회전** + 중앙 지지 파일런·아웃트리거·크로스브레이스 + **점멸 비컨** + 좌우 **항법등** — 구조 픽셀 **17,472px**.

## 4.8 채굴 소행성(빠뜨렸던 항목) · 원거리 함대 · 1px 방어포격 · 함선 장갑 · 허공발사 제거

**점검 결과 빠뜨린 항목 1건을 찾아냈다**: 예전에 요청한 **자원 채굴 소행성 + 채굴선**이 미구현이었다. 큰 암석의 약 8%를 **광맥 암석**으로 지정해 ① 몸체에 **금/은/카나가와 크리스탈 블루 광맥**(시드로 선택)을 넣고 ② **채굴 드론 1~3기가 궤도를 돌며** ③ 드론에서 암석으로 **1화면px 채굴 빔**을 쏘는다(프래그먼트 단위 측정). 검증: 벨트 프레임에서 광맥/채굴 요소 **624px** 검출.

**허공 발사 제거**: 탄이 빈 공간에서 나오던 원인은 **① 도착 전(inS<0.85) 함선도 발사**했고 **② 이미 격추된 적함을 계속 조준**했다. 둘 다 막았다 — 발사는 도착 후에만, 표적은 생존한 적함만(아군·대공 모두).

**함대를 먼 곳으로**: 함체 크기를 결정하는 depth를 전면 하향(적함 0.90→**0.50**, 아군 방어함 0.92→**0.55**, 일반 아군함대 0.48~1.38→**0.30~0.70**, 순찰 0.95→**0.60**). 작고 먼 느낌이 나고, 행성 스케일 앞에서 부담스럽지 않다.

**함선 래스터 1px화**: 함체의 국소 좌표가 `floor(center)` — 즉 **논리핀셀(4px)에 고정**돼 있어 위치를 1px로 스냅해도 그림이 4px씩 건너뛰었다(사용자: “가끔 안 될때가 있다”). `floor(center*px)/px` 로 **물리px 앵커**로 교체(적함·아군함·일반 함대).

**방어포대 이펙트 1px화**: 대공포격 탄을 **프래그먼트 단위**로 측정해 **폭 0.8화면px**(이전 0.7논리px=2.8화면px), 머즐 섬광도 2.5논리px→**2화면px**로 축소.

**함선 장갑 디테일**: 행성과 같은 단일 광원 원칙으로 함체에 **밝은 상단 엣지·그늘진 옆구리·함교 블록·포탑 점·적/청록 항법등**을 추가(아군·적함 공통, 적함은 진홍 계열 유지).

검증: 강제 렌더 2종(`v48-belt.png` 채굴 광맥, `v48-view.png` 작아진 함대 + 1px 대공포격) · `shader-lint` 무이슈(14 컨트롤) · 4K 0.59~0.97ms.

⚠ 컴파일 기록 2건: ① 채광 빔이 `fragCoord`를 쓰는데 `asteroidGroup`에 인자가 없었다 → 인자 추가 ② `fleetHull` 블록에 `shell` 변수명을 잘못 썼다(그 함수는 `metal`) → 교정.

## 4.7 이동 전면 물리1px화 · 소행성 내부 끓음 제거 · 정거장 리디자인 · 순찰 · 함선 실드

**모든 이동 객체를 행성과 같은 방식으로 통일했다** (`snapFine` = 물리 1px 격자 스냅): 혜성/별동별 머리·꼬리, 스타게이트·정거장, 아군함대, 조준점까지 전부 적용되어 4px 점프가 사라졌다.

**소행성 ‘지글거림’의 진짜 원인**: 실루엣이 `noise2(floor(d/2.5))` — **절대 격자에 고정된 노이즈**라 암석이 미끄러질 때 **내부 패턴 전체가 끓었다**(행성은 국소좌표를 양자화해 안 그럼) → 실루엣을 **각도의 매끄러운 함수**(3·5엽 로브)로 교체하고 크레이터 2개를 **암석 고정 위치**로 바꿈 → 경계가 픽셀을 넘을 때만 변한다.

**우주정거장 리디자인**: 밴드 척추 + 허브 + **회전 거주링(창문이 같이 공전)** + **액자형 태양전지 4장(체커 패턴)** + 도킹 암·**점등 포드** + **적/청록 항법등** + **점멸 비컨 마스트** + 척추 창문 — 행성과 같은 단일 광원·단일 팔레트(쿨 그레이 + 금색 창)로 통일. 크기도 0.030→0.036 기저로 키워 디테일 공간을 확보했다.

**스타게이트/정거장 가시성**: 슬롯 240→**150초**, 스킵 50→**35%**, 지연 10~180→**5~40초**. 또 **슬롯보다 수명이 길어 슬롯 경계에서 잘려나가던 버그**를 수정(수명 110~170→**70~105초**) — 이래서 한 번도 못 보셨을 가능성이 크다.

**순찰 모션 신규**: `patrolPass()` — 1~3척이 **워프 없이 행성급 저속**(150~190초 통과)으로 지나가며, 완만한 위빙으로 레일처럼 보이지 않게 했다.

**함선 실드**: 함대함 교전에서 함선도 피탄 시 **자기 실드(작은 육각, 반투명)**로 막는다 — 적함은 적자색 `(206,116,152)`, 아군은 청록 `(150,220,240)`. 실드는 격추 **0.9초 전에 깨지며** 작은 육각 섬광이 번쩍인다(이후 탄은 선체에 적중). 크기는 행성 글린트보다 작게(반지름 2.8~3.0px) 유지 — 절제 원칙 그대로.

검증: 강제 렌더 3종(`t3-check.png`: 정거장 / 순찰 / 함선 교전) · `shader-lint` 무이슈(14 컨트롤) · 4K 0.44ms. ⚠ 함선 실드 글린트는 0.25초 창이라 이 프레임엔 잡히지 않았다(코드 경로는 검증된 행성 육각과 동일).

⚠ 컴파일 기록: 순찰이 `fleetHull`을 호출하는데 **전방 선언이 아래에 있어** 실패 → 선언을 헬퍼 블록 바로 뒤로 올림(모든 사용자보다 위).

## 4.5 궤도링 방어포대 점검 (지속 포격화)

사용자 지적: “행성에서 날아가는 수비포대 대함포격이 안 보인다.” 점검 결과 **두 가지 결함**이 있었다.

1. **발사가 너무 드물었다**: 정거장이 **격추 직전 0.45초**에만 발사 → 40초 교전에서 각 정거장이 1발 → 사실상 보이지 않음.
2. **발사 원점이 정거장과 어긋났다**: `stationPoint(0.65+m*TAU/3 + iTime*iCityFlow*0.022)` — 뒤의 **회전 항** 때문에 발사점이 그려진 정거장에서 계속 미끄러져 **허공에서 탄이 나가는** 상태였다(그려지는 정거장은 고정 각도).

**수정**: 정거장 **3곳 × 2문**이 1.25초 주기로 **지속 사격**(비행 0.55초 → 항상 2~3발이 동시 비행), 발사 원점은 **그려진 고정 각도**로 교정, 발사 순간 **머즐 플래시**(2px) 추가. 탄은 목표를 순환 배정해 여러 적함을 향해 흩어진다. 격추 폭발은 그대로 유지(격추 시각이 곧 그 탄의 명중 시점).

검증: 강제 교전 프레임에서 **청록 방어포격 2,944px**(이전엔 0~수백 px, 단발) · bbox x 1264~2683 · 4K 0.86ms · `cf5-view.png`.

⚠ 컴파일 오류 수정 기록: 내부 루프 변수명을 바꾸면서 폭발 코드가 참조하던 `shipPx`가 스코프 밖이 됐다(`undefined variable`). 폭발 직전에 `shipPx`를 다시 계산해 해결. 한 번 깨진 셰이더가 설치됐으나, 앱은 **로드 실패 시 이전 정상 셰이더를 유지**하도록 되어 있어 화면은 무사했다.

아카이빙: 4.4는 `-v4.4.glsl`, 현재 4.5는 `-v4.5.glsl` 스냅샷과 동일.

## 4.4 소행성·함선 이동을 물리 픽셀 단위로 (끊김 제거) · 혜성 꼬리 비드

**끊김의 정체**: 모든 이동 객체를 **논리 픽셀(4물리px) 격자**에 스냅하고 있었다. 소행성 무리는 초당 30논리px로 움직여 60fps에서 **한 프레임에 4px, 다음 프레임에 0px**을 반복 — 눈에는 “끊김”으로 보인다.

### 실측 A/B (암석 하나만 크롭해 1/60초 간격 두 스텝 측정)

| 버전 | 프레임0→1 | 프레임1→2 |
| --- | --- | --- |
| v4.2 논리4px 스냅 | **+4.00px** | **+0.00px** (멈춤) |
| v4.4 물리1px 스냅 | **+1.37px** | **+0.96px** (일정) |

**수정**: `snapFine(v)=floor(v*px)/px` — 위치를 **물리 픽셀(1px) 격자**에 스냅한다. 표면 샘플링은 여전히 블록 격자라 모양은 픽셀아트로 남고, 이동만 4배 섬세해진다(창 크기 기준 1화면px 단위라 모양 왜곱도 눈에 띄지 않는다). 소행성 무리·적함·아군함·조준점에 적용 — **느려진 함대의 기동 끊김도 함께 해결**된다.

**혜성·별동별 꼬리도 같은 원리로 수정**: 임의 각도의 얇은 선은 진행할 때마다 재래스터화되어 **가장자리가 좌우로 부르르 떨린다**(사용자 지적). 꼬리를 **격자에 스냅된 픽셀 비드 체인**(혜성 12개, 별동별 8개, 뒤로 갈수록 작고 어둡게)으로 교체해, 각 비드가 1px씩 평행이동만 한다. 부수적으로 클래식 픽셀아트 혜성 실루엣이 된다.

검증: `shader-lint` 무이슈(14 컨트롤) · 4K 0.44~0.60ms. ⚠ 혜성 꼬리의 떨림 제거는 **구성상 보장**(모든 비드가 스냅된 위치만 참조)이며, 패턴 IoU로 측정하려던 시도는 서브픽셀 이동에서 모양이 미세하게 달라져 지표로 씨울 수 없었다.

아카이빙: 4.2는 `-v4.2.glsl`, 현재 4.4는 `-v4.4.glsl` 스냅샷과 동일.

## 4.2 큰 쉴드 형상 전면 제거 · 직선 포격 · 이펙트 추가 축소

**행성을 감싸는 쉴드 형상을 모두 없앴다.** 4.1에서 행성 링을 지웠고, 이번에 **궤도링을 감싸던 육각 고리까지 제거**했다 — 이제 화면에 쉴드를 나타내는 형상은 **피격점의 아주 작은 녹색 육각 글린트뿐**이다. 궤도링도 쉴드를 *가지긴* 한다(상태는 살아 있고 링을 노린 탄의 글린트로만 보인다).

**포격이 발사 각도 그대로 직선으로 간다**: 이전엔 탄의 시작점을 **현재 함체 위치**로 잡아서, 함선이 느리게 흘러가도 빔 전체가 매 프레임 회전해 **휘는 것처럼** 보였다. 이제 탄은 **발사 순간의 함체 위치**에서 시작한다:

```glsl
float launchAge=age-bAge;
float tLaunch=smoothstep((launchAge-2.0)/(life-3.4));
vec2 firingPos=raiderPos(mix(entryP,exitP,tLaunch)*size.y, ...);
vec2 dirB=normalize(hitPt-firingPos);
```

→ 탄마다 고정된 직선 궤도.

**이펙트 추가 축소**: 빔 폭 **0.8 → 0.5 논리px**(4K에서 2물리px — 선이 성립하는 최소), 빔 길이 9→11, 지표 미세섬광 1.8→**1.2px**, 녹색 육각 2.6→**1.9px**, 격추 폭발 4.2→**2.8px**, 대공·아군 볼트도 폭 0.5px로 통일.

검증: 강제 촬영에서 **녹색 픽셀 0**(육각 고리 제거 확인) · `shader-lint` 무이슈(14 컨트롤) · 4K 0.79ms.

아카이빙: 4.1은 `-v4.1.glsl`, 현재 4.2는 md5 `d41d510b32115a804c4a3d63895ab43e` / `-v4.2.glsl`.

## 4.1 함대 기동 완화 (워프아웃 구현) · 행성 쉴드 링 제거

**함대가 너무 빨랐고, 워프아웃 없이 사라졌다.** 셋을 고쳤다:

1. **수명 13~17초 → 30~40초**. 실측 이동 속도 2초에 0.0324 화면폭(0.016/s) — v3.8의 약 **1/6**.
2. **Smoothstep 기동**: `travel=smoothstep((age-2)/…, 0,1)` — **빠른 진입 → 폭격 중 느린 정지(hold) → 빠른 이탈**. 일정 속도로는 항상 너무 느리거나 빨랐다.
3. **함선별 시차 진입**: `inS=clamp((age-1.6-id*0.45)/2.2,0,1)` — 한 줄이 한꺼번에 나타나지 않는다.
4. **워프아웃 구현**: 함체 스케일을 `lenS*(1+outP*3.0)`, `widS→0.04`로 수축시켜 **게이트 안으로 빨려들며 소멸**한다(이전엔 이벤트 종료 시 전원이 한 프레임에 증발).
5. 격추 시각 재조정(적함 `8+2.6·id`, 아군 `12+2.8·id`) — 30~40초 교전에 맞춤.

**행성 쉴드 링 제거**: 요청대로 **행성을 둘러싼 링은 그리지 않는다**. 실드가 작동하는 증거는 **피격 지점의 작은 반투명 녹색 육각형**뿐이다 — 반지름 2.6→0.8px로 줄이고 `mix()` 블렌딩(0.55/0.28)으로 바꿔 은은하게. 쉴드 *상태*는 여전히 차단 판정·육각 생성 여부를 결정한다.

**궤도링 쉴드**는 유지(이전 요청)하되 훨씬 은은하게(블렌딩 0.42/0.18).

검증: 쉴드 업 프레임에서 녹색 육각 착탄(`bomb-view.png`, v4.0) / 쉴드 다운 프레임에서 지표의 **작은 분홍 섬광**과 **링 없음**(`b41-view.png`)을 각각 확인.

검증: `shader-lint` 무이슈(14 컨트롤) · 4K 0.5~0.9ms.

아카이빙: 4.0은 `-v4.0.glsl`, 현재 4.1은 `-v4.1.glsl` 스냅샷과 동일.

## 4.0 포격 스케일 정정 (얇게·多數) · 녹색 육각 쉴드 · 궤도링 쉴드 · 소행성 색상 감사

**이펙트를 행성 스케일로 줄였다**: 행성은 함선의 수백 배이므로 굵은 빔은 “페인트 줄”처럼 보였다.

- 볼트: 길이 18·**폭 1.6논리px**(이전 14×3) — 얇은 레이저
- 볼트 수: 함선당 **1발 → 3발**(발사주기 1.15초 내 0.38초 시차)로 **대규모 포격** 느낌 유지
- 착탄 섬광: 11px 버스트 → **3~4px** 마이크로 버스트 + 얇은 링
- 격추 폭발: 15px → **9px**, 링도 얇게. 지속 0.6초는 유지
- 대공포격 볼트도 폭 1.6px로 통일

**착탄 분포**: 기존엔 모든 탄이 행성 **가장자리** 한 줄에 맺혀 링처럼 보였다 → 이제 조준점을 원반 **내부**(반지름 0.30~0.92배)에 분산 + 횡 오프셋 → 표면 곳곳에 떨어진다.

**녹색 육각 쉴드 이펙트**: 착탄점에 `hexEdge()`(정육각형 경계 거리) 기반 **녹색 육각형**(152,216,180)이 번쩍이고, 초기 0.3초는 안쪽을 얇은 녹색으로 채운다. 카나가와의 청록 계열이라 씬과 색이 맞는다.

**궤도링 전용 쉴드**: 링(궤도 레일)에 **자체 주기를 가진 두 번째 쉴드**(`shieldState(incAttack*0.93+1.7, seed+7.0)`)를 줬다. 레일을 따라 **길쭉한 육각형**으로 표시되며 행성 쉴드와 **다른 시점에 깨진다**. 편대 일부(id 4·8)는 행성 대신 **링을 포격**한다.

**소행성 색상 감사**: 이전 톤 (96,92,84)/(134,128,116)/(52,50,48)은 **노란기 도는 따뜻한 회색**으로 카나가와 잉크 계열이 아니었다 → **(88,90,96)/(124,126,132)/(50,52,60)/(150,152,156)/(36,38,46)** 쿨 그레이로 교체. 따뜻한 색은 의도된 곳(금색 도시 불빛·황토/화산 행성)에만 남는다. 검증: 구 톤 0px / 신 톤 2224px.

검증: `shader-lint` 무이슈(14 컨트롤) · 4K 0.56~0.88ms · `bomb-view.png`(얇은 볼트·녹색 육각 착탄·궤도링 녹색 쉴드), `belt-colour.png`(쿨 그레이 소행성).

## 3.9 지나가는 스타게이트 / 우주정거장

**느린 통과물**: `structureSchedule()` + `structurePass()` 추가. 240초 슬롯 · 50% 조용 · 지연 10~180초 → **대략 4~8분에 한 번**. **110~170초에 걸쳐 천천히** 지나간다 — 빠른 소행성 무리·함대와 달리 **행성급 속도**다.

## 3.8 적함 다양화 · 행성 가시성 게이트 · 아군 방어함대 교전

**적함 5종 · 대수 확대**: 기존 3종(시드·크랩·스파이어)에 **만타**(넓은 델타+후퇴익)와 **하이브 마더**(길쭉한 포드 모함, 함체 74×40 유닛 — 가장 큰 적함)를 추가했고, 편대를 **4~9척**(이전 3~6)으로 늘렸다.

**행성이 안 보이면 공격 안 함**: 도시 행성의 원반이 화면 밖이면 `planetVisible=false` → 수명을 6.5초로 줄이고 `attack=0` — **워프인 후 잠시 대기했다가 그대로 워프아웃**한다(빈 하늘에 포격하지 않음).

**아군 방어함대 + 함대함 교전**: 침공 시드의 55%에서 **방어함대 3~5척**이 같은 레인의 반대쪽(오른쪽)에서 워프인해 맞붙는다.

- 아군은 **자기 게이트·자기 함체**(기존 `fleetHull` 회청색 팔레트)·**자기 격침 시각**(`defenderDownTime`)을 가진다.
- **적함 절반(홀수 id)은 행성 대신 아군함을 노린다**: 조준점이 아군함 위치로 바뀌고, 명중하면 그 자리에서 폭발한다.
- 아군도 **1.05초 주기로 청록 볼트**를 쏘아 적함을 격추시킨다. **양쪽 모두 손실**이 발생한다.
- 전투 중에도 궤도링의 대공포격(정거장 3곳)은 계속된다.

검증: 강제 셰이더로 교전 중간(age=4.0초)을 렌더 — 적함 **4129px**(신규 하이브 마더 포함), 청록 볼트 **1152px**, 그리고 일반 아군함대·소행성 이벤트를 모두 끈 상태에서 **회청색 아군 함체가 적함 옆에 존재**하는 것을 눈으로 확인(`df-only-view.png`).

검증: `shader-lint` 무이슈(14 컨트롤) · 4K 0.66~0.79ms.

아카이빙: 3.6은 `-v3.6.glsl`, 현재 3.8은 `-v3.8.glsl` 스냅샷과 동일(3.7의 픽셀 스냅과 침공 주기 단축도 포함).

## 3.6 메가폴리스 방어전 (쉴드 생성/파괴 · 궤도링 반격)

침공 때 도시 행성이 **실드를 전개**하고 적의 포격을 **막거나 뚫리고**, 궤도 링의 정거장이 **반격해 적함을 격추**한다.

**쉴드 (`shieldState`)**: 상태를 저장하지 않고 **사건 시계의 순수 함수**로 만든다.

- 생성 0.9초(강도 0→1) → 유지(피격 누적에 따라 **0.55까지 흐려짐** = 버티는 느낌) → **파괴**(0.30초 백색 팽창 링) → 3.0~4.6초 다운 → 재생성. 용량은 8~13발(시드).
- **차단 판정**: 실드가 살아 있으면 적탄의 **종점이 반경 1.06 지점**으로 바뀌고 **차가운 청록 섬광**이 링에 맺힌다. 실드가 내려가면 종점이 **표면**이라 **뜨거운 주황 섬광**이 지표에 떨어진다 — 이 차이가 “막았다 / 맞았다”를 그대로 보여준다.
- 렌더: 지구본 바깥 **하드 1.5px 링**(아군 함대 색과 구분되는 청록·연보라).

**궤도링 반격**: 정거장 3곳이 **각각 적함 한 척씩**을 노리고(0.45초 비행) **격추 시각 이후 그 함선은 편대에서 사라진다** — 편대가 눈에 띄게 줄어든다. 격추 지점에는 **줄어드는 폭발 섬광 + 팽창 링**이 0.6초간 맺힌다.

검증(`shield-phases.png`): t=4233/4236 **쉴드 링 있음** → t=4239.5 **링 사라짐**(누적 파괴) ✓. `boom.png`에서 **청록 반격 볼트가 비행 중**인 것 확인 ✓. 폭발은 강제 시각 셰이더로 **창 진입(화면 전체 마커)과 위치(논리 24px 대역)를 각각 확인**했다.

⚠ 기록: 처음 만든 폭발 창이 0.187초(6→0px로 급감)라 대부분 프레임에서 안 보였다 — 0.6초(7→-1px)로 수정. 1프레임짜리 플래시는 폭발로 읽히지 않는다.

검증: `shader-lint` 무이슈(14 컨트롤) · 4K 0.44~0.86ms.

## 3.4 적 외계 함대 침공 (워프인 → 공격 → 워프아웃)

## 3.2 직선 궤도 · 이동 속도 완화

**직선 궤도**: `orbitLane`의 수직 보빙(`mid + height*sin(...)`)을 제거하고 **`y = mid` 고정**으로 바꿨다. 항성계 내부에서 비스듬한 궤도를 보면 선으로 보이는데, 흔들리는 경로는 계속 어색하게 읽혔다(사용자 지적). 이제 각 천체는 자기 높이(`mid`)의 **직선 레인**을 좌→우로 지나간다. 쓰이지 않게 된 `height` 인자는 시그니처에서 제거하고 호출부 6곳을 갱신했으며, 미사용이던 `orbit()` 래퍼도 삭제했다.

**속도 완화**: 드리프트 계수 `0.006 → 0.0022`(약 2.7배 느리게). 실측 20초간 x 이동 **0.072 화면폭**(이전 0.216~0.29) → 화면 횡단에 수 분이 걸린다.

**랩 여유 추가**: 스팬에 `+0.6`을 더해 랩 시점에 몸체가 가장자리에 걸쳐 보이지 않게 했다(이전 스팬 계산에는 여유가 없어 오른쪽 끝에서 일부가 보일 수 있었다).

검증: `shader-lint` 무이슈(14 컨트롤) · 4K 0.28~0.40ms · y중심 0.557 → 0.544(직선 확인) · x 속도 0.0036 화면폭/초.

아카이빙: 3.1은 `-v3.1.glsl`, 현재 3.2는 `-v3.2.glsl` 스냅샷과 동일.

## 3.0 종단선 하드 라인 제거 (디더 램프)

**증상**: 명부/암부 경계에 **한 줄로 그어진 그림자 같은 선**이 보였다(사용자 지적).

**원인 두 가지**:

1. 1.8에서 넣은 **종단 노을선** — `if(band>0.5 && band<1.5) c=mix(c, (104,74,54), 0.40*iRim)` 로 디스크를 가로지르는 고체 색 라인이었다.
2. 2.7의 albedo 조명이 **5단 하드 스텝**(0.20/0.46/0.70/0.88/1.0)이라 경계에서 계단이 생겼다.

**수정**: `ditherLevel(v, pixel, steps)` 공용 헬퍼를 추가해 성운과 **같은 디더 기법**을 조명에 적용했다(바이어 65% + 해시 지터 35%).

- 도시 행성 조명: `lit = 0.18 + 0.82*ditherLevel(clamp((light+0.10)*1.25,0,1), pixel, 8)` — **8단 디더 램프**
- 노을선: 하드 라인 삭제 → `warm = ditherLevel(1-|light|*4, pixel, 3)` 로 **밝기에 따라 사라지는 디더 띠**
- 자연 행성(가스·사막·빙결·화산·해양·달)도 같은 방식으로 노을 띠를 디더 처리(`planet()`에 `pixel` 인자 추가)

검증: `shader-lint` 무이슈(14 컨트롤) · 4K 0.663ms · 검정 53.7% · 확대 `crop-term30.png`(경계가 점묘로 녹아들고 선이 없다).

아카이빙: 2.9는 `-v2.9.glsl`, 현재 3.0은 `-v3.0.glsl` 스냅샷과 동일.

## 2.9 별 순서 수정 (행성 관통 제거)

2.8에서 별 블록을 **삭제한 자리에 그대로** 넣었다(편집은 제자리 치환) — 그래서 순서가 바뀌지 않았고, 가드만 사라져 별이 행성 **위에** 그려졌다. 별이 행성을 관통해 보인 것이다(사용자 지적).

**수정**: 별 블록을 **원거리 행성 뒤 · 근거리 천체 앞**으로 실제로 이동. 이제 가림은 전적으로 **그리기 순서**가 담당한다 — 행성이 자기 원반으로 별을 덮고, 옆 하늘의 별은 그대로 남는다.

**검증**: 행성 원반 안 밝은 점 5277 → **3914**(별이 덮임), 주변 고리 18383 → 16948(대기 헤일로가 가장자리 별을 덮음). 확대 `crop-halo29.png` — 행성 옆 하늘은 별로 가득, 원반에는 별이 없다.

**교훈(기록)**: 제자리 치환 편집으로는 레이어 순서가 바뀌지 않는다 — 순서를 바꾸려면 블록을 **다른 위치로 옮겨야** 한다. 그리고 A/B 검증은 주변만 보지 말고 **대상(원반) 내부**까지 확인할 것. 이번에 주변만 보고 넘겼다가 사용자가 먼저 발견했다.

검증: `shader-lint` 무이슈(14 컨트롤) · 4K 0.658ms · 검정 53.7%.

아카이빙: 2.8은 `-v2.8.glsl`(순서 버그판), 현재 2.9는 `-v2.9.glsl` 스냅샷과 동일.

## 2.8 별을 배경으로 (행성 그림자 제거)

**증상**: 행성 주위에 **별이 전혀 없는 검은 고리**가 생겨 행성이 하늘에 그림자를 드리운 것처럼 보였다(사용자: “별이 그림자에 가려질 리가 없잖나”).

**원인**: 별을 행성보다 **나중에** 그리면서 `empty` 가드로 제외 반경을 두고 있었다. 도시 행성은 `length(q)>1.75` — **반지름의 1.75배** 안쪽에서 별을 전부 지웠다(괴도 구조물을 피하려던 값이 너무 컸다).

**수정**: 별 필드를 **배경으로 먼저** 그린다(원거리 행성 뒤, 근거리 천체 앞). 그러면 행성은 **자기 원반만** 가리고 주변 하늘에는 별이 그대로 남는다. 가드(`empty`)는 완전히 제거했다. **원거리 행성은 의도적 예외**로 별보다 먼저 그려, 별이 그 앞을 지나가는(거리감) 효과는 유지.

**A/B 검증**: `halo-ab.png` — 좌(v2.7): 행성 옆이 별 없는 검은 고리 / 우(v2.8): 별이 행성 가장자리까지 가득. 고리 영역 별 밀도 37.1 → 39.2/1000px(영역 대부분이 성운으로 덮여 수치 상승은 작지만, 근접 영역은 0 → 정상밀도).

## 2.7 종단선 자연화 (albedo 우선) · 초미니 별가루

**종단선(명부/암부 경계) 처리 재설계**: 이전엔 대륙·구름·해안선을 `if(band>1.5)` 안에서만 그려서 **종단에서 뚜욱 끊겼다**. 이제 **표면(albedo)을 태양과 무관하게 먼저** 만들고(대륙 2톤·해양·대륙붕·구름 2톤·도시 콘크리트 계획), 그 뒤에 조명을 **5단 양자화 배수**(band 0/1/2/3/4 → 0.20/0.46/0.70/0.88/1.0)로 적용한다. 밤 반구는 단순 감광 대신 **차가운 색조**(`*vec3(0.78,0.90,1.15)`)를 섞고, 도시 야경 조명은 별도로 모아 **조명 적용 뒤**에 더한다(`lights`). 그래서 구름과 해안선이 종단선을 **자연스럽게 넘어간다** — 실제 행성처럼.

**초미니 별 추가 + 개수 증가**:

- `stars()`에 **17px 미세 레이어** 추가(논리 1px 점)
- `starDust()` 신설 — **물리 1픽셀** 점을 화면공간에서 샘플(9px 셀, seed>0.80). 뮤럴의 유일한 **의도적 4px 격자 예외**이며 AA 없는 하드 픽셀
- 밀도 상향(`0.30+0.95*cloud` → `0.36+1.15*cloud`)
- 결과: 하늘 영역 별 픽셀 **2032 → 7014 (3.5배)**

**작업 중 발견한 버그(기록)**: 조기 반려 리팩터에서 `if(!hit) return` 검사를 빼먹어 별이 화면 전체를 덮었다(검정 비율 53.8%→**25.9%**, 별 픽셀 **501,315**). 수치 지표로 즉시 발각해 복구했다 — 시각만 봤으면 놓쳤을 종류의 실수다.

**비용**: 4K 오프스크린 **0.66ms**(별 레이어가 주 비용; 밀도 구름은 프레임당 1회로 끌어올렸다). 앱 창 크기(4K의 약 1/6)에서는 약 0.11ms 수준.

검증: `shader-lint` 무이슈(14 컨트롤) · 검정 53.8% · 자료 `crop-city27d.png`(구름·대륙이 종단을 넘어가고, 밤 쪽 도시 조명과 별가루).

아카이빙: 2.6은 `-v2.6.glsl`, 현재 2.7은 md5 `99afe7bcc9505f557d5f0a3c82a9f811`(정본=설치=`-v2.7.glsl`).

## 2.6 공전 좌→우 통일 · 점유율 제한 · 혜성 다방향 · 별 다양화

**공전 방향 통일**: 모든 천체가 **좌→우**로 이동한다(`orbitLane`을 닫힌 타원에서 **긴 선형 드리프트 + 화면 밖 랩**으로 교체). 랩은 천체가 화면에서 완전히 벗어난 지점에서만 일어나므로 이음매가 보이지 않는다(스팬에 +0.6 여유 포함). 실측: 같은 몸체가 10초에 +0.108, +0.146 화면폭 이동.

**동시 등장 수 제한**: `spanScale`이 이동 경로를 늘린다 — 작으면(1.0) 사이클의 45%를 화면에 머무르고(주인공 행성), 크면(3.2~5.0) **가끔만 지나가는 방문객**이 된다. 6장 표본(t=12/120/240/360/480/600)에서 **동시 등장 1~2개**, 한 장은 빈 하늘(이전 최대 6개).

## 2.5 행성 5종 · 원거리 행성 · 레인 분리

**행성 종류 5종**(`planet()`의 kind 분기): 0 = 가스 행성(벤드+폭풍) · 1 = 황토 사막(분화구) · **2 = 빙결**(극관·균열선·가장 차가운 색) · **3 = 화산**(현우암 평원 + 야간에 빛나는 용암 균열·분출구) · **4 = 해양**(짙은 청색+군도+대륙붕). 화산은 도시 행성의 야경처럼 **밤 쪽에서 용암이 빛난다**.

**원거리 행성**: `farBody`(0.042, kind 4)이 `rate 0.14`의 작은 느린 레인을 돌며, 그려진 뒤 **배경색과 0.70 비율로 mix되어 안개에 잠긴다**. 별 가림 검사에서 **일부러 제외**해 앞쪽 별들이 지나가게 했다 — 그게 거리감을 만든다.

**레인 분리**: `orbitLane(aspect, phase, rate, amp, mid, height)`로 천체마다 진폭·수직 중심·높이를 따로 준다(기존 `orbit()`은 호환용 래퍼). 그래서 모두 같은 타원을 쓸지 않는다:

| 천체 | amp | mid | height | rate |
| --- | --- | --- | --- | --- |
| 도시(0.19) | 0.78 | 0.50 | 0.25 | 1.0 |
| 가스(0.15, 고리) | 0.62 | 0.30 | 0.16 | 0.87 |
| 황토(0.074) | 0.86 | 0.72 | 0.20 | 0.73 |
| 빙결(0.095) | 0.55 | 0.14 | 0.10 | 1.35 |
| 화산(0.062) | 0.70 | 0.86 | 0.10 | 0.55 |
| 원거리(0.042) | 0.30 | 0.60 | 0.08 | **0.14** |

검증: `shader-lint` 무이슈(14 컨트롤) · 4K 0.269~0.279ms(천체 8개 평가에도 여유) · 검정 50.3~58.7%(시각별) · 3시점 자료 `planets-v25.png`. 천체가 많아진 만큼 별 가림(`empty`)에 빙결·화산 실루엣을 추가했다.

## 2.4 성운: 정렬 디더 램프 · 성진 · 등고선 제거

**핵심 기법**: 밴드 경계를 **ordered dither**로 넘긴다. `bayer2`/`bayer4`(4×4 바이어)를 **논리 픽셀 격자**에서 읽고, 램프의 소수부가 임계값을 넘으면 한 레벨 올린다 — 셀은 하드 픽셀로 남고 거리에서 보면 부드러운 그라데이션으로 읽힌다(픽셀아트에서 램프를 위장하는 전통 기법).

**유기적 지터**: 순수 바이어는 규칙적인 스크린도어 패턴으로 보이고 순수 해시는 노이즈가 된다. `thr = bayer4(pixel)*0.65 + hash21(pixel+3.0)*0.35`로 섞어 규칙성을 없앴다.

**등고선 제거**: `contour<0.12 → +1레벨` / `contour>0.85 → -1레벨` 리본이 지형도처럼 보여 제거했다. 남은 리지는 `detailN>0.72 && n>0.55 && mod(floor(bank*5),4)==0`로 매우 드물게.

**성진(星塵)**: 밴드 안에 논리픽셀 단위로 0.25% 확률로 밝은 점을 뿌린다(`hash21(pixel+7.0)>0.9975`).

**램프 보정**: 디더가 평균 0.5레벨을 더하므로 램프를 그만큼 내려(`(bank+0.21)*2.3`) 은하 면적을 v2.3과 같게 유지했다 — 검정 비율 61.04%(v2.3은 60.78%), **중앙 텍스트 밴드 검정 93.17%**로 가독성도 유지.

검증: `shader-lint` 무이슈(14 컨트롤) · 4K 0.252ms · 확대 `crop-neb24c.png`(유기적 디더 페이드 + 성진, 등고선 없음).

아카이빙: 2.3은 `-v2.3.glsl`, 현재 2.4는 `-v2.4.glsl` 스냅샷과 동일.

## 2.3 구름 자체 흐름 · 잘게 (행성 크기는 원복)

**구름이 행성 안에서 따로 흐른다.** 이전에는 구름을 지표와 **같은 회전 프레임**(`s`)으로 샘플해서 지표와 함께만 돌았다 — 그래서 멈춘 것처럼 보였다. 이제 `cloudSpin = angle*2.4 + iTime*iSurfaceSpeed*0.010`으로 **표면보다 약 2.4배 빠른 자전**을 주고, 위도 전단(`+vec2(q.y*0.35,0)`)을 더해 위도별로 속도가 다르게 만든다. 같은 행성 영역의 13초 변화가 70.1%로 측정된다(이전엔 표면 회전만이라 미미).

**뿌연 문제**: 한 톤의 부드러운 wash를 `mix`하던 것을 **임계값 2톤 하드 패치**로 바꿨다 — `cloud>0.76` → `(140,148,150)` 0.70, `cloud>0.58` → `(112,120,124)` 0.58. 또 노이즈 주파수를 2.3→3.6으로 올려 패치가 작고 많아졌다.

**행성 크기**: 2.2에서 `CITY_R`을 0.15로 줄였는데, 사용자 피드백(“크기는 아까처럼 큰게 좋다”)에 따라 **0.19로 원복**했다. 달 궤도(0.27/0.24)·달 반지름(0.025)·식 그림자 반지름(0.16)·가림 판정 거리(0.027/0.03)도 함께 원복.

검증: `shader-lint` 무이슈(14 컨트롤) · 4K 0.259ms · 검정 60.78% · 확대 `crop-city23.png`(작은 구름 패치 다수, 도시 구조, 해안선, 간선도로).

아카이빙: 2.2는 `-v2.2.glsl`, 현재 2.3은 md5 `f58d1ef8c118c8000fab1c8b7aa51b1b`(정본=설치=`-v2.3.glsl`).

## 2.0 함대 규모 확장 (클래스 · 함종 6종 · 원거리 대함대)

**함대 클래스**: `fleetClass(seed)`가 슬롯마다 3종 중 하나를 고른다 — 소규모 편대(2~4척, 약 30%), 일반 기동함대(4~7척, 약 52%), 원거리 대함대(12~18척, 약 18%). 대함대는 수명이 16→22초로 길고 편대 간격(0.30초)도 넓어 대형이 펼쳐지듯 등장한다.

**함종 6종**: 니들 프리깃 / 광폭 순양함 / 격납고 항모 / **드레드노트**(장갑 슬래브 + 계단 함수 + 아웃리거 포드 + 금장 척추, 최대 88×40 유닛) / **코르벳**(짧은 다트, 대함대 호위) / **수송함**(화물 격자). 대함대는 드레드노트 1척이 선두, 이후 순양함·프리깃·코르벳 혼성.

**원거리 연출**: 대함대는 depth를 0.18~0.38의 좁은 대역으로 묶어 **모든 함선이 작고 어둡게** 나온다(화면상 함체 16~35 논리픽셀). 12~18척이 0.014 간격 종대로 늘어서 멀리서 접근하는 함대처럼 읽힌다.

**성능**: 게이트 작업을 자체 bbox(60px×depth)로 조기 반려하고 함체 판정도 `|s.x|<48 && |s.y|<22`로 먼저 걸러, 18척에서도 프레임 비용이 꾸준하다 — 4K 오프스크린 0.34ms(소규모)/0.39ms(일반)/0.54ms(대함대).

검증 방법론(중요): 셰이더의 `hash21`을 파이썬(float64)으로 복제하면 GLSL(float32)과 임계값 근처에서 갈린다 — `find_fleets.py`가 대함대라고 계산한 시각(t=1140)이 실제로는 일반 함대로 렌더됐다(렌더 차이 0.00%로 발각). 그래서 **클래스를 강제한 임시 셰이더**(`float r=0.95;` 등)로 각 클래스를 렌더해 검증했다: `fleet-forced.png`(위→아래 소규모/일반/대함대). 검증 후 임시 파일은 삭제했다.

아카이빙: 직전 1.9는 `-v1.9.glsl`(md5 `d25bf772…`), 현재 2.0은 md5 `486155ad1a2ff4183d1b0a7a96b3105e`(정본·설치·스냅샷 동일, 691줄).

## 1.9 별 시차 · 혜성 · 위성 식 · 구도

**별 시차**: `stars(pixel, cellSize, driftRate, boost)`로 바꿔 레이어마다 다른 정수픽셀 크롤 속도를 줬다. 29px 레이어는 정지(driftRate 0), 47px는 1.0, 71px는 2.2 — 화면에 깊이감이 생긴다. 스텝은 여전히 `floor()`된 논리픽셀이라 서브픽셀 이동은 없다.

**혜성**: `cometSchedule()`이 240초 슬롯·약 38% 스킵·무작위 지연으로 결정적 일정을 만들고(배의 일정과 같은 아이디어), `cometPixel()`이 진행도 0→1을 9초에 걸쳐 그린다. 진입/이탈점을 **화면 단위**로 지정해(좌상단 → 우하단) 항상 프레임 안에 들어오게 했고, 머리는 2논리픽셀 블록, 꼬리는 42논리픽셀 테이퍼 웨지에 4단 플랫 톤이다. `iWarpRate`가 0이면 배와 함께 혜성도 멈춘다.

**위성 식**: 달 그림자는 달의 위치가 아니라 **광원에서 달을 지나는 광선이 구와 만나는 점**에 떨어진다(달은 행성 반지름의 약 1.4배 밖을 돈다). 이차방정식 광선/구 교차로 그 점을 구해 반지름 0.16(행성 반지름 단위) 원반을 `×0.42`로 어둡게 한다. 반대로 달이 행성 그림자 원통 안에 들어가면 달 자체가 `×0.35`로 어두워진다. 광원의 z가 낮아(0.42) 부식점이 가장자리 쪽에 생기는데, 이는 기하학적으로 정확한 결과다. 시각은 `find_events.py`가 셰이더와 **동일한 해시/궤도 산술**로 계산해 찾는다(첫 프레임 안 식: t=1594.5s, 달이 광원 축에서 0.145 반지름).

**구도**: `CITY_R = 0.19`(0.205에서 축소) 상수로 정리하고, 궤도 가로 진폭을 `0.86 → 0.78`, 각 천체 높이를 낮줘(도시 0.29→0.25, 황토 −0.33→−0.30, 가스 0.36→0.32) 천체가 화면 밖에 오래 걸치지 않게 했다.

검증: `shader-lint` 무이슈(Controls 14). 4K 중앙값 0.272ms. 검정 59.6~60.8%. `check_starbound_translation.py` 4px블록·1px이동 통과(레이어별 크롤 후에도). 시각 검증 = `crop-comet4.png`(머리+꼬리), `crop-eclipse2.png`(달 그림자 원반).

## 1.8 조명 체계화 (밴드 · 3구역 림 · 명부 구조)

**문제였던 것**: 1.7까지 명암은 도트곱을 손으로 고른 임계값(`-0.10 / 0.26 / 0.35 / 0.50`)으로 자른 3~4단 톤이라 종단선이 실제 dot=0에 있지 않았고, **암부는 단일 톤 하나**여서 “희불한 그림자 덩어리”로 보였다. 도시 야경은 암부에서 1.65배 부스트에 교통 펄스가 얹혀 반짝였다.

**광원 기준(변경 없음)**: `lamp = (iResolution.x/iResolution.y*0.32, -0.35)`, `light = normalize(vec3(lamp-center, 0.42))` — 화면 고정 램프 위치, z=0.42(앞쪽). 노멀은 해석적 구 노멀 `(q, sqrt(1-|q|²))`. 행성이 궤도를 돌면 방향이 매 프레임 재계산된다.

**새 체계**: `lightBand(d)`가 도트곱을 **5단 밴드**로 양자화한다 — **0=밤(<-0.06), 1=종단(|d|<0.06), 2~4=명부 3단(0.06/0.34/0.62)**. 모든 천체(가스·황토·위성·도시)가 같은 밴드 팔레트를 쓰고, 세 구역이 각자 림을 가진다:

| 구역 | 림 처리 |
| --- | --- |
| 종단(1) | 따뜻한 노을선 `mix(c, (104,74,54), 0.40·iRim)` |
| 명부(2~4) | 밝은 쪽은 `(83,116,130)`, 중간은 `(58,80,94)` |
| 암부(0) | 차가운 저채도 림 `(30,46,60)`, 0.35·iRim |

디스크 **밖** 헤일로도 같은 3구역 논리를 쓴다(명부 1.0/0.45, 종단 0.30, 암부 0.22) — 그래서 암부에도 경계가 생겨 덩어리로 떠 보이지 않는다.

**도시 야경 안정화**: 교통 펄스를 78% 정적인 `steady`(주기 약 39초)로 대체하고 야간 부스트를 1.65→1.25로 낮춰 암부가 “지도”로 읽히게 했다.

**명부 구조**: 대낮 반구가 평평하게 비어 보이는 문제를 잡기 위해, 밤야경이 따르는 **같은 대륙 마스크**로 낮엔 대륙(+12,14,13)·해안 대륙붕·구름 덮개를 그리고, 정착지(메가시티/타워/도로)는 낮에 **회색 확장(grey sprawl)** 으로 보이게 분기했다(밤=빛, 낮=구조).

검증: `shader-lint` 무이슈(Controls 14). 4K 중앙값 0.257ms. 검정 비율 60.75%(유지). `check_starbound_translation.py` 4px블록·1px이동 통과. 확대 검증 = `crop-city18.png`(명부 구조 전), `crop-city18d.png`(후), `crop-gas18.png`(가스 행성 고리 그림자·종단 노을선).

아카이빙: 직전 1.7은 `-v1.7.glsl`(md5 `fcb006c7…`), 현재 1.8은 md5 `3689e3000dd520f2b7c3f0e70403cafa` (정본·설치·스냅샷 동일).

## 1.7 림 절제 / 살아있는 성운

**대기 림을 훨씬 연하고 얇게** 다시 잡았다. 1.6은 2~3px 두께의 2단 하드 링이었는데, 이제 **1물리픽셀**(`1.0/(iResolution.y*radius)`)이고 색도 훨씬 어둡다(`vec3(34,56,70)/255`, 밝은 쪽 100% · 어두운 쪽 45%). 행성 안쪽은 밝은 하이라이트 대신 미세한 리프트(`mix(c, vec3(66,92,106), 0.40*iRim)`)로 바꿨다. 기존에 있던 밝은 림 호(`89,109,117`)도 `mix(..., 0.30*iRim)`으로 눌렀다. 도시 행성도 같은 처리이며 디스크 밖 헤일로는 1.6px 두께로 줄였다. 새 컨트롤 **Atmosphere Rim**(`iRim`, 기본 0.5)으로 더 낮추거나 0으로 끌 수 있다.

**성운이 살아 움직인다**. 1.6까지 성운 띠는 완전히 정지해 있었다. 새 컨트롤 **Nebula Life**(`iNebulaLife`, 기본 0.7)가 네 가지를 한꺼번에 조절한다:

- **크롤**: 노이즈 샘플 위치를 정수 논리픽셀 단위로 이동(`floor(iTime*life*0.16)`). 이동하는 것은 *노이즈*뿐이고 띠 경계는 화면 좌표(`uv.y`)에 고정되어 있으므로, 텍스트가 앉는 조용한 중앙은 영원히 그대로다. 이게 핵심 설계다.
- **크기 호흡**: `breathe = 1.0 + 0.16*sin(period ~3분)`이 노이즈 주파수를 키웠다 줄여 띠의 결이 굵어졌다 가늘어진다.
- **경계 파동**: `wave`/`upperBase`의 진폭·주파수가 저주파로 흔들려 띠의 모양과 자리가 천천히 출렁인다(±13 논리픽셀 수준).
- **색온도 드리프트**: 띠 색이 보라(`44,34,56`)↔차가운 청록(`26,48,54`) 사이를 왕복한다. `k>=2`(성운 띠)에만 적용해 검정 영역과 그 위 텍스트는 절대 변하지 않는다. 1.6의 정적 보라 악센트는 이 드리프트로 대체했다.

검증: `shader-lint` 문제 없음(Controls **14**). 4K 독립 렌더 중앙값 0.254ms(iTime 12). 검정 비율 60.75%(1.6은 62.23% — 띠가 호흡하며 조금 넓어진 시점). t=12 ↔ t=240 비교: **33.9% 픽셀이 변화**(살아있음), 중앙 밴드의 검정 비율 **92.8% → 96.1%** 로 조용한 중앙 유지. A/B = `ab-v16-v17.png`. `check_starbound_translation.py`의 4px 블록·1px 이동 검사는 그대로 통과.

아카이빙: 직전 1.6은 `kanagawa-starbound-v1.6.glsl`(md5 `569897cb…`), 현재 설치본은 1.7(md5 `fcb006c7aa387c1fdf09de228ce42de1`, `kanagawa-starbound-v1.7.glsl` 스냅샷 동일). 두 폴더 모두 보존.

## 1.6 대기 림 · 고리 그림자 · 해안선 조명 · 별 밀도

행성에 **대기 림**을 추가했다. `bodyLocal`이 반지름으로 정규화하므로 1물리픽셀을 국소좌표로 환산해(`2.0/(iResolution.y*radius)`), 밝은 쪽 림에 2~3px 두께의 2단 하드 링을 그린다. 도시 행성은 디스크 밖 헤일로를 따로 그려 궤도 구조물보다 뒤에 오게 했다. 그라데이션·AA는 쓰지 않는다.

**고리 그림자** 두 겹: ① 행성이 자기 고리에 드리우는 원통형 그림자(고리 뒤쪽이 어두워진다), ② 고리가 행성 원반에 드리우는 띠(고리 평면을 따라 램프 반대 방향으로 0.12 이동, 밝은 면에만 적용). 램프 방향은 행성 프레임에서 계산하며, 길이가 0일 때 `normalize`가 NaN을 만들지 않도록 가드를 두었다.

**해안선 밀집 조명**: 대륙 마스크(`land`) 경계 0.06 이내를 해안으로 보고 그 지역에서 도로/타워 임계값을 낮춘다(0.42→0.20, 0.84→0.70). 내륙은 성기게 남아 야경이 지도처럼 읽힌다.

**별 밀도 구름 + 3번째 레이어**: 별 존재 여부를 저주파 구름(`noise2(pixel*0.0031)`)으로 변조해 빈 공간과 밀집 띠를 만든다(위치 기반이라 시간 불변). 29/47px 레이어 위에 71px 레이어(십자 반경 ×2)를 추가해 근거리감을 준다.

검증: `shader-lint` 문제 없음(Controls 12). 4K 독립 렌더 중앙값 0.216ms / p95 0.2247ms(iTime 12), 검정 비율 62.28%(1.5는 62.19%)로 텍스트 영역의 어둠은 그대로다. `check_starbound_translation.py` = `city_local_blocks_are_4px: true`, `physical_1px_translation_exact: true`. A/B 자료: `kanagawa-starbound-ab-v15-v16.png`(기본 시점), `ab-gas15-gas16.png`(t=300s, 가스 행성 고리 그림자), `crop-crisp16.png`(NEAREST 확대 — 모든 경계가 하드 블록). `render_check.py`는 이제 `t=초`로 임의 시점을 렌더한다.

## 1.5 혼성 편대 / 압축·팽창 워프

3~5척 편대: 바늘형 호위함, 넓은 쌍갈래 순양함, 긴 격납고 항모. 각 함선은 자체 위치·깊이·함종·시차를 가진 시간 기반 개체이며, 먼 순서부터 그린다. 작은/어두운 원거리 함선과 큰/밝은 근거리 함선으로 거리감을 준다. 이벤트마다 편대 위치와 방향이 달라지고 각 함선의 워프 진입/이탈 위치도 다르다.

워프인: 좁은 실루엣이 펼쳐지고 청록·보라 이중 균열이 팽창한다. 워프아웃: 선체가 길게 늘어나며 폭이 줄고 게이트 안으로 압축된 후 소멸한다. 게이트 내부 감광과 윤곽선 팽창으로 표현하는 시각 효과이며, 배경 좌표를 실제 굴절시키는 렌즈 효과는 아니다. 텍스트 합성은 영향을 받지 않는다.

4px 개체별 격자 + 물리1px 이동 유지. 무한 정밀도의 서브픽셀 이동/AA는 사용하지 않는다. 이벤트 일정과 컨트롤은1.4와 동일. 이전1.4를 `kanagawa-starbound-v1.4.glsl`로 보존했고 설치본은1.5다.

검증: shader-lint 및 기존 렌더/공전/이동/이벤트 생애 검사 통과. 첫4개 편대 실제 렌더 `fleet-variants.png`, 등장/소멸 `ship-lifecycle.png`, 전체 구도 `ship-preview.png`. 독립OpenGL4K 이벤트 활성 상태 중앙값 약0.27ms. 앱 전체 프레임 비용 또는120fps 지속 성능을 의미하지 않는다. `par-term-fleet.png`는 이벤트 이전의 앱 렌더다.

## 1.4 전함 워프 이벤트

같은 4px 해상도와 청회색 장갑·금빛 창·청록 엔진으로 전함을 추가했다. 약16초 동안 출현→느린 순항→가속 워프→소멸. 워프는 작은 국소 궤적이며 전 화면 플래시 없음. 함선은 전경으로 합성한다.

Ship Event Frequency: 기본1, 0이면 이벤트 끔. 기본180초 구간마다 해시로 지연과 발생 여부를 정해 간격을 흔들며 일부 구간은 건너뛴다. Ship Event Brightness: 기본0.65. 주파수는 간격만 바꾸고 비행은16초 유지. 같은 셰이더 시간에서는 같은 사건이 나오는 결정적 의사난수다. 기본 첫 사건은 약41.7초(앱의 셰이더 시계 기준), 첫1시간에13회. 블러 일시정지/시간 리셋에 따라 실제 대기시간은 달라질 수 있다.

기존1.3은 `kanagawa-starbound-v1.3.glsl`로 보존. 설치본1.4를 사용하려면 셰이더 재선택. 현재 config와 앱 빌드 변경 없음.

## 1.3 거대도시 / 이동 격자 분리

밤 쪽 불빛 배율 1.0→1.65, 낮 쪽 0.35→0.20. 동심원 구획과 방사형 도로를 가진 거대도시 3곳 및 장거리 연결 도로 추가. 시각적 야간 대비 강화이며 실제 광도 모델은 아니다.

행성마다 자체 4px 픽셀 격자를 사용한다. 이전 고정 배경 격자에 묶인 4px 점프를 없애고 물리1px씩 위치를 옮긴다. AA나 색 보간은 하지 않는다. `check_starbound_translation.py`로 4px 단색 블록 및 정확한 1px 평행이동을 실제 GLSL에서 검증했다. 기존 공전/반짝임 검증도 통과.

시간 기반 셰이더라 60/120fps 모두 동작한다. 현재 앱 설정 `max_fps: 60`은 유지했다. 120Hz 화면에서 `max_fps: 120`으로 설정하면 상한을 올릴 수 있다. 실제 앱의 지속120fps를 측정한 것은 아니다. 느린 이동에서는 1px 미만 변위를 표시하지 않으므로 120fps여도 매 프레임 다른 위치가 되는 것은 아니다. 완전한 서브픽셀 부드러움에는 경계 보간/AA가 필요하다.

독립4K OpenGL 중앙값0.177ms, p950.179ms. 이전1.2는 `kanagawa-starbound-v1.2.glsl`로 보존. 현재 설치본 `kanagawa-starbound.glsl`은1.3. `par-term-megacity.png`는 앱 렌더.

## 1.2 공전 / 문명 행성

큰 행성을 청록·보라·금빛 야간 도시가 흐르는 문명 행성으로 변경. 궤도 레일, 정거장 3개, 엘리베이터 케이블과 왕복 캐빈, 링 위 이동체 3개를 추가했다. 뒤쪽 시설은 행성에 가려진다. 자연 고리 가스행성은 별도로 등장하며 황토색 행성과 작은 위성도 유지한다. 블록 크기는 4px 그대로다.

화면 밖까지 이어진 닫힌 타원 경로로 행성들이 교대한다. 기본 문명 행성 주기는 약 18분, 다른 행성은 다른 속도다. 물리 시뮬레이션이 아닌 배경용 구도다. 고정 광원에 대한 행성 위치·표면 방향으로 명암을 계산하고 몇 단계의 단색으로 표현한다. 밤에는 도시 불빛이 더 잘 보인다. 표면은 느린 2D 회전 무늬다.

새 컨트롤: Planet Orbit(0이면 위치 고정), Surface Motion(0이면 표면 정지), City Traffic(0이면 불빛 흐름·시설 이동 정지), City Lights(밝기). 별의 움직임/반짝임은 기존 별도 컨트롤이다. 모든 움직임을 멈추려면 이 세 속도와 Star Drift, Twinkle을 모두 0으로 설정한다.
