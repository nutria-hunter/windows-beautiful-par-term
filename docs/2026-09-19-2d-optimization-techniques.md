# 2026-09-19 — 2D/풀스크린 최적화 기법 조사와 적용 결과

목표: AMD 내장그래픽에서 배경 셰이더가 GPU를 100% 포화시키지 않게 하면서 **현재 화질을 유지**.
(별개로 `power_preference: high_performance` 로 RTX 5090을 쓰면 내장은 0%가 된다 — `2026-09-19-igpu-low-power-and-scaled-variant.md`.)

## 조사한 기법과 판정

| 기법 | 출처 | 판정 |
| --- | --- | --- |
| 저해상도 렌더 + 업스케일 (FSR1 = EASU+RCAS; "naive 업스케일은 흐릿") | GPUOpen FSR1/CAS, Babylon.js FSR1 문서 | **적용**: 4K→정수 2배(1920×1080) 축소 + `textureLoad` nearest |
| 텍스트는 네이티브 합성, 셰이더 좌표는 배율로 보정(`iReadability.zw`) | 구현 설계 | **적용**: 셰이더는 여전히 4K로 인식 → 픽셀 그리드/디더 유지, 글자 무손실 |
| 텍스처 캐싱("cache as texture": 안 변하는 레이어는 재렌더 안 함) | PixiJS `cacheAsTexture`, 정적 타일맵 프레임버퍼 캐시 | **적용**: 축소 배경 텍스처를 재사용해 애니메이션 30fps, 정지 시 1fps |
| CAS/FSR 샤프닝 | GPUOpen CAS/RCAS | **제외**: 이 아트워크는 의도된 디더+블록 그리드 → 정수배수+nearest가 정합적, 샤프닝은 블록 경계 증폭 |
| VRS(가변 셰이딩 레이트) | Intel Xe-LP 최적화 가이드 | **불가**: wgpu가 `VK_KHR_fragment_shading_rate` 미노출 |
| fp16 정밀도 | wgpu PR#5701, gpuweb#2524/#3524 | **보류**: `SHADER_F16` 요청 + 셰이더 변환 필요 |
| 정적 레이어 분리(패럴랙스) | 패럴랙스 레이어 기법 | **보류**: 단일 프로시저 셰이더 분해는 대공사, 잠재 이득 최대 |
| 단일 패스/오버드로 회피 | Intel 개발자 가이드 | 이미 준수(셰이더 1패스 + 합성 1패스) |

## 실측 (AMD Radeon 내장, 창 2360x1412, `power_preference: low_power`, 프로브가 포커스 상태)

방법: 같은 바이너리를 24~26초 실행하고, Windows GPU Engine 카운터에서 **해당 프로세스의 3D 사용률만**
0.9초 간격으로 12회 샘플 → 앱이 실제로 그리는 구간(>1%)만 모아 **중앙값**을 쓴다.
(초기 셰이더 컴파일/시작 스파이크를 중앙값이 제거한다. 앞선 보고의 97%/51%는 이 스파이크를 peak로 잡은 오측이었다.)

| 구성 | 내장 3D 중앙값 |
| --- | --- |
| 이전 빌드 · 배경 정지 (풀해상도, 합성 패스 없음) | 49.3% |
| 새 빌드 · 배경 정지 (0.5배 + 매 프레임 합성) | **10.5%** (4.7배 절감) |
| 이전 빌드 · 애니메이션 (풀해상도 60fps) | **106.3%** (포화 = 사용자가 겪은 렉) |
| 새 빌드 · 애니메이션 (0.5배 + 30fps 스로틀) | **52.1%** (2.0배 절감) |
| 셰이더 끔 (앱 자체: 셀/egui) | 6.6% |

### 이 숫자가 말하는 것 (비용 모델)

정지·애니메이션 두 경우를 같은 식으로 풀면, 이 창 크기에서

- **매 프레임 고정비(앱 자체 + 전체해상도 합성) ≈ 9%** (앱 6.6% + 합성 ≈2.4%)
- **셰이더 1회 렌더(0.5배) ≈ 1.5%** → 30fps면 ≈ 44%

즉 애니메이션 배경은 매 프레임 창 전체를 다시 그려야 하므로 **고정비 9% 아래로 내려갈 수 없다.**
"내장 10% + 애니메이션 + 4K"는 구조적으로 불가능하고(4K면 고정비만 ~22%), 가능한 조합은:

| 목표 | 설정 | 내장 사용률 |
| --- | --- | --- |
| 정지 배경(권장) | `custom_shader_animation: false` | **~10.5%** |
| 정지 + 저프레임 | 위 + `max_fps: 30` | ~5% |
| 애니메이션 유지 | 현행 0.5배 + 30fps | ~52% (4K에서는 더 높음) |
| 애니메이션 + 내장 부하 없음 | `power_preference: high_performance`(5090) | **내장 0%, 5090 3~6%** |

## 적용한 코드

- `par-term-render/src/custom_shader_renderer/scaled_background.rs` + `.wgsl` (축소 타깃 + 네이티브 합성)
- `par-term-render/src/custom_shader_renderer/mod.rs`: 축소 타깃 생성/합성 배선 + **배경 재사용 스로틀**
  (애니메이션 30fps·정지 1fps, 새 타깃 생성 시 즉시 재렌더, 직접 출력 경로는 무변경)
- `par-term-render/src/cell_renderer/mod.rs`: `Selected GPU: <이름> (<종류>, <백엔드>); preference=<설정>` 로그

## 적응형 배율 (내장그래픽만 있는 PC용, 2026-09-19 추가)

해상도 기준 배율만으로는 부족했다: 1080p 창은 축소가 0(divisor 1), 4K 창은 항상 2배에서 멈춘다.
느린 내장과 빠른 내장을 창 크기로 구분할 수 없기 때문이다. 그래서 **배율이 프레임률을 따라간다**:

- 프레임률이 50fps 미만으로 **3초 연속**이면 배율을 한 단계 굵게(최대 4배 = 1/4 해상도)
- 창 크기가 바뀌면 해상도 기준 바닥값에서 다시 탐색
- **다시 가늘게 되돌아가지 않는다**(래치). 양방향으로 두었을 때 실제로 4초마다 `2→3→4→3→2` 왕복이
  발생해 렌더 타깃을 계속 재생성하고 배경 크기가 눈에 띄게 바뀌었다.
- `custom_shader_full_content`(커서/전체 콘텐츠 효과)와 discrete GPU는 배율 1 고정

실측(AMD Radeon 내장, 3840x2160, 애니메이션 켜짐): 23fps에서 한 번 `divisor 2 → 3`(1280x720)으로
내려간 뒤 **더 이상 변하지 않고 유지**되었다. 1080p 창에서도 같은 규칙이 적용되므로, 내장만 있는
PC에 설치해도 설정을 손대지 않고 스스로 맞춘다.
