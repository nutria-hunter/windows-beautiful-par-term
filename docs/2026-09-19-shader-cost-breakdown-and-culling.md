## 적용한 최적화 — 화면공간 컬링 2개

`warshipArt` 앞에는 이미 스프라이트 바운딩 컬이 있었다. 남은 낭비는 **픽셀과 무관한 계산을 매
픽셀 수행**하는 것이었다: 편대 전체가 화면의 좁은 띠/코리도 안에서만 움직이는데, 띠 밖 픽셀도
함선 9~18척의 위치·게이트·실드·볼트 계산을 전부 치렀다.

1. `incursionEvent`: 레이더 띠(`lane`)와 목표 행성/링을 감싸는 **가로 띠** 밖이면 함수를 즉시 반환.
2. `shipEvent`: `origin` 을 지나는 **편대 코리도**(측면 0.62 화면높이, 진행 -0.85~+0.35) 밖이면 즉시 반환.

둘 다 보수적 여유를 둔 비교 1~2회이므로 **그림이 바뀌지 않는다**.

### 결론(증거 기반)

남은 비용은 이벤트 장면의 **아주 많은 소규모 픽셀 연산에 얇게 퍼져** 있고, 개별 헬퍼를 노린 미세
최적화는 수확 체감(0~0.5%)이다. 실제로 큰 다음 수단은:

1. **프레임당 상수 사전계산(pre-pass LUT)** — 이벤트 상태(함선 위치·조준점·스케줄)를 픽셀마다
   다시 계산하는 대신, 작은 오프스크린 패스가 텍스처에 한 번 써 두고 모든 픽셀이 샘플.
   (Unity: "프레임당 한 번 계산해 셰이더로 전달", NVIDIA: "미리 계산한 값은 SRV/LUT 로")
   → **앱 기능 추가 필요**(채널 텍스처에 써 넣는 경로).
2. **노이즈/난수 텍스처화** — 앱이 이미 `custom_shader_channel0..3` 을 지원하므로 노이즈 PNG 를
   동봉해 `stars`(10%)·성운의 fbm 을 샘플로 대체(proceduralpixels 사례 4~5배). 단 노이즈 값이
   바뀌므로 **그림이 미세하게 달라진다**(작가 튜닝 재확인 필요).
3. **fp16**(`SHADER_F16`): 레지스터·대역폭 절감, 실측 필요.
4. **해상도·프레임 스케일링**: 이미 자동 적응형으로 구현(무식하지만 확실).

## 3차: unroll 폭탄 제거 — 동적 루프 경계 (−6.9%, 픽셀 동일)

`for(int j=0;j<26;j++) { if(j>=count) continue; ... }` 처럼 **고정 상한 + count 가드**를 쓰는 루프 8개는
컴파일러가 본문 전체를 26·18·9회 복제한다(코드 100 KB+, 레지스터 압박 → 점유율 저하).
경계를 `min(count,원래상한)` 로 바꾸면 전개가 불가능해지고 **의미는 완전히 동일**하다.

| 루프 | 변경 |
| --- | --- |
| `asteroidGroup` | `for(j<26)` + `j>=count` → `for(j<min(count,26))` |
| `shipEvent` | `for(j<18)` → `for(j<min(count,18))` |
| 습격 편대 / 잔해 | `for(j<9)` → `for(j<min(count,9))` |
| 방어 편대 / 정거장 | `for(k<3)`, `for(m<3)` → `for(k<min(count,3))` 등 |
| 드론 / 방어기 | `for(k<min(drones,3))`, `for(k<min(dCount,5))` |

측정: 0.7933 ms → **0.7389 ms (−6.9%)**, 렌더 차이 평균 **0.0000/255** (픽셀 동일).

## 5차: 3차 측정(레이어별)과 지연 노이즈 — 교란의 교훈

3차에서 `noise2` 26.7%, `starDust` 14.8%, `depthComposite` 78% 가 나왔지만 **모두 교란값**이었다.
`noise2` 를 0으로 만들면 성운 밀도가 0이 되고, 그 밀도가 별 가시성 분기(`seed > 0.36+1.15*cloud`)를
지배하기 때문에 **장면 전체의 분기가 닫힌다**. `depthComposite` 는 모든 합성을 담당하므로 더 명백하다.

그래서 실제로 안전하게 줄일 수 있는 중복을 찾아 적용했다 — 행성 함수가 **분기와 무관하게**
가스형 전용 `detail`, 암석형 전용 `land`, 화산형 전용 `basalt` 노이즈를 먼저 계산하던 것을 각 분기
안으로 옮겼다(값 동일, 지연 평가).

측정: 0.7392 ms → 0.7425 ms — **차이 없음**, 픽셀 동일. 하네스가 측정하는 시점의 가시 행성 종류가
이미 그 노이즈를 쓰고 있었기 때문으로 보인다.

### 교훈 (측정 방법론)
스텁(stub) 기반 비용 귀속은 **그 함수가 여는 분기까지 함께 사라져** 과대평가된다.
`hash21` 72.7%, `noise2` 26.7%, `depthComposite` 78% 는 모두 이 함정이다.
신뢰할 수 있었던 것은 **분기 구조를 바꾸지 않는 변경**(컬링, 동적 루프 경계)의 실측이었다.
