## 시각적 변경

- **구도**: 중심 (62%, 58%), 위치각 −25도, 투영 단축비 0.48. 외곽 팔이 화면 밖으로 이어진다. 좌상단은 넓은 검정 여백.
- **코어**: 작고 밝은 핵(거의 흰색) + 불균일하게 어두운 팽대부. 암부가 코어를 관통한다.
- **팔**: 주 나선팔 2개 + 부분적으로만 나타나는 세 번째 팔. 팔마다 밝기·폭이 다르다.
- **팔레트**: 외곽은 남색·청색·청록, 내부는 샴페인 금빛·상아색. 무지개식 순환 없음.
- **암부**: 주 팔의 안쪽 가장자리에 붙은 긴 먼지길 2줄 + 팔을 끊는 넓은 틈.
- **별구름**: 3픽셀 블록 면 + 제한된 밝기 단계(기본 8) + 비반복 해시 디더. 규칙적 Bayer 디더가 아니다.
- **별**: 1×1 기본, 드물게 2×2. 전부 축정렬 정수 픽셀 사각형. 블러·블룸·AA·시간 누적 AA 없음.
- **정지 배경 별밭**: 화면 격자 23px·47px 두 겹. **위치가 절대 움직이지 않고 밝기만 맥동**한다.
  별마다 위상과 주기가 다르고, 파동의 골에서 최대 18%까지 어두워진다(음수가 되지 않도록 설계).
- **발광 결절(H II)**: 팔을 따라 늘어선 밝은 덩어리. 외곽은 청록, 내부는 장미빛 금색.
- **코어 내부 구조**: 핵 주위에 더 촘촘히 감긴 내부 나선이 별도로 있어 코어가 단조롭지 않다.
- **가스 성운**: 은하를 감싸는 반투명 베일. 팔을 따라 흐르고 곳곳에 구멍이 뚫려 있어 뒤의 검정이 비친다.
  외곽은 남보라, 내부는 장미빛. 기본값 0.22로 절제되게 유지한다.
- **부드러운 은하 본체**: 하이라이트 롤오프 `v / (1 + 0.45·v²)` 로 핵이 흰색으로 뭉개지지 않게 하고,
  자체 노이즈로 구멍이 뚫린 확산 헤일로를 더해 원반이 "빛의 구름"으로 읽히게 했다.
  팔레트 단계를 10으로 올려 밴딩도 줄였다. **실제 은하처럼 선명하지 않다.**
- **핵의 부피**: 팽대부를 원반과 다른(더 둥근) 지표로 측정해 원반에서 돌아나온 회전타원체처럼 보이게 했다.
  암부가 팽대부를 비스듬히 가로지른다.
- **애니메이션**: 은하 전체가 원반 좌표계에서 강체 회전. 기본 0.015 rad/s (한 바퀴 약 7분).
  별은 정지한 채 밝기만 맥동하며, 반짝임 깊이는 `iTwinkle` 0에서 0, 1에서 0.85다.

## 구조 설계

| 함수 | 역할 |
| --- | --- |
| `screenToDisk` / `diskToScreen` | 화면 ↔ 기울어진 회전 원반 좌표 변환. 화면 높이로 정규화하므로 종횡비에 왜곡이 없다. |
| `armPhase` / `armArc` / `armProfile` / `armEnvelope` | 주 나선팔·보조 팔의 밀도. 로그 나선. |
| `riftField` → `dust` (인라인) | 암흑 먼지길과 분기, 팔을 끊는 틈. |
| `cloudField` → `clus`, `clus2` (인라인) | 별구름의 큰·작은 밀도 변화. |
| `rampCool` / `rampWarm` | 제한 팔레트와 픽셀 명암. 0 지점은 순수 검정. |
| `starDensityAt` | 별 존재 확률. **별 자신의 원반 좌표의 함수**이므로 시간에 대해 불변. |
| `diskStars` | 별 위치·크기·밝기·색. 회전 격자 + 정수 픽셀 스냅. |
| `foregroundStars` | 전경 별. 화면 격자 + 독립 표류. |

### 좌표 변환

```
p = (px - center) / screenHeight
q = R(-positionAngle) · p
D = (q.x, q.y / inclination)          // 정지 원반 좌표
d = R(-orbitAngle) · D               // 회전 원반 좌표 (모든 장이 여기서 정의됨)
```

### 별 렌더링 (핵심)

"화면 픽셀을 역회전해서 셀 해시를 조회"하는 방식은 별이 회전된 모양으로 잘리거나 크기가 변한다.
여기서는 반대로 한다.

1. 별은 **회전하는 원반 격자**의 셀에 산다. 셀 크기 기본 7px(주축 기준).
2. 프래그먼트의 원반 좌표로 3×3 이웃 셀을 조회한다 (후보 9개).
3. 후보 별의 원반 좌표를 **화면으로 변환한 뒤 정수 픽셀로 스냅**한다.
4. 스냅된 좌상단을 기준으로 **축정렬 하드 사각형**을 그린다. 판정은 정수 비교이므로 AA가 구조적으로 불가능하다.

**탐색 범위 정당성**: 화면에서 2px 떨어진 별의 원반 좌표 거리는 단축 방향으로 `2 / (H·inclination)`이다.
셀 크기를 `max(cellPx, 2.6/inclination)`로 강제하면 이 값이 항상 셀 크기보다 작아지므로 3×3 탐색이 충분하다.
기본값(inclination 0.48)에서 셀 7px > 2.6/0.48 = 5.4px 이다.

**비용**: 별 후보 9개 × (해시 2회 + 변환 + 판정). 은하 밖(`rn > 1.45`)에서는 존재 확률이 0이라 루프가 즉시 빠져나간다.

### 감쇠 일관성

암부 감쇠는 프래그먼트 단위로 한 번 계산해 별 후보에 재사용한다.
먼지길 폭이 셀보다 훨씬 크므로 별 하나의 픽셀 간 차이는 무시할 수 있고,
**별의 원반 좌표가 시간에 대해 불변**이므로 회전 중에 별이 갑자기 켜지거나 꺼지지 않는다.

### 가독성

**스크린샷으로 "은하 위 텍스트"를 검증하지 못했다.** `--command-to-send` 와 `initial_text` 로 창을 채우려 했으나
스크린샷이 셸 출력보다 먼저 찍혀서, 실제로는 은하만 있는 화면이 나왔다.
따라서 아래 수치는 **텍스트가 놓일 배경의 밝기 분포**이며, 텍스트 대비의 입력값으로만 쓴다.

실제 par-term 창(1251×734, 은하만 표시):

| 영역 | 평균 | p95 | 최대 |
| --- | --- | --- | --- |
| 좌측 검정 영역 | 0.95 | 0.00 | 0 |
| 은하 영역 (x ≥ 500, 하단) | 13.55 | 77.5 | 255 |
| 화면 전체 | 7.57 | — | 255 |

앱은 텍스트를 배경과 무관하게 같은 밝기로 합성한다(설계상 `custom_shader_text_opacity = 1.0`).
은하 코어(최대 255)가 텍스트 뒤에 오면 대비가 사라지므로, 그 구간에서는 **작업용 프리셋**을 쓰거나
`iCenterY` 를 낮춰 코어를 화면 아래로 보내는 편이 낫다.
실제 창에서 눈으로 본 결과 코어를 피한 영역(좌측·상단)의 텍스트는 선명하다.

**검증하지 못한 것**: 코어·팔·암부 위에 텍스트를 올린 상태의 실제 스크린샷.

## 구현 중 확인한 사실

- **팔레트 램프의 0 지점은 반드시 순수 검정이어야 한다.** 처음에는 0 지점을 남색 `(0.012,0.024,0.078)`로 두었더니
  밀도가 0인 픽셀도 luma 6.8이 되어 **원반 전체가 평평한 남색 판**으로 보였다.
  완전 검정 비율이 0.623에 고정되고 원반 안에 검정 픽셀이 하나도 없어서 발견했다.
- **중심부 로그 나선의 과도한 감김을 약화해야 한다.** 그대로 두면 팔이 중심에서 서로 겹쳐 원반이 채워진 판이 된다.
  `log(max(rn, 0.30))`으로 감김을 포화시키고 팔 진폭을 `smoothstep(0.10, 0.42, rn)`으로 서서히 켠다.
- **양자화 + 디더는 희미한 밀도를 증폭한다.** 단계가 5개면 한 단계가 0.2이고 디더가 ±0.275단계라
  밀도 0.05가 밝기 0.2로 올라간다. 단계를 8로 올리고 디더를 ±0.11단계로 줄이고 저역 소프트 플로어를 넣었다.
- **moderngl `Query.elapsed`는 나노초**다. 4K 프로브 3.78ms, 1080p 0.84ms로 픽셀 수에 정확히 비례함을 확인했다.
- **타이밍 루프 전에 프레임버퍼를 바인딩해야 한다.** 안 하면 렌더가 기본(사실상 0×0) 프레임버퍼로 가서
  224ns 같은 무의미한 값이 나온다.

## 알려진 한계 / 남은 문제

- **반짝임 식이 음수가 될 수 있다.** `0.45 + 0.55*sin` 은 골에서 -0.1 이 되어 별이 빛을 *뻐앗는다*.
  `0.5 + 0.5*sin` 으로 바꾸고 깊이를 `0.18 + 0.82*pulse` 로 묶어 항상 0 이상이 되게 했다.
- **밝기를 낮추면 색도 같이 변한다.** 하이라이트 롤오프를 0.85로 세계 걸었더니 코어의 v가 낮아져
  팔레트 웜 램프의 중간 구간으로 내려가 **눈부신 흰색이 탁한 갈색**이 되었다. 밝기를 낮출 때는
  롤오프를 절반(0.45)만 걸고 게인을 같이 올려서 코어가 색 램프의 위쪽에 남게 해야 한다.
- **확산 헤일로는 구멍을 뚫어야 한다.** 균일한 헤일로는 완전 검정 비율을 0.743 → 0.445로 무너뜨렸다.
  헤일로 자체 노이즈에 smoothstep을 걸어 약 30%를 0으로 만들어야 검정이 살아남는다.
- **새 필드를 추가하면 "별만 보는" 테스트를 같이 고쳐야 한다.** 가스 성운을 넣은 뒤 테스트를 그대로 두었더니
  회전하는 가스가 별 마스크에 섞여 별 사각형 검증과 정지 별밭 검증이 동시에 실패했다.
  별 전용 테스트는 `iGasGain = 0` 까지 꺼야 한다.
- 회전이 **강체**이므로 별이 팔에 대해 상대적으로 움직이지 않는다. 초안은 "원반 별이 형태보다 조금 빠르게"를 원했는데,
  차등 회전은 격자를 전단시키고 시간이 지나면 별이 팔에서 대거 이탈하므로 넣지 않았다.
  전경 별의 독립 표류와 반짝임이 대신 움직임을 만든다.
- `iPaletteSteps`를 8보다 낮추면 밴딩이 거칠어지고, 2~4에서는 계단이 눈에 띈다.
- `iInclination`을 0.2 아래로 낮추면 셀 크기 하한이 커져 별이 성겨진다(정확성 유지 비용).
- 셰이더가 매 프레임 픽셀당 4개 필드를 fbm으로 계산한다. `iQuality=0`이 가장 싸다.
- 이 문서의 성능 수치는 **독립 OpenGL 오프스크린 측정**이며, 앱 전체 프레임 시간·전력·지속 부하는 측정하지 않았다.
- **은하 위 텍스트 가독성을 스크린샷으로 검증하지 못했다** (자동 스크린샷이 셸 출력보다 먼저 찍힘). 배경 밝기 분포만 기록했다.
- 넓은 창(16:9)만 확인했고, 세로로 긴 창·좁은 창에서의 구도는 확인하지 않았다.
- 앱 자체의 별도 GPU 시간 보고 수단은 사용하지 않았다.
